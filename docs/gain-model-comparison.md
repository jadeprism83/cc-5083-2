# 增益模型对比实验：网格插值场 vs 受约束基函数

本文件记录照明增益表示的技术选择实验。所有数值都可以用
`npm run compare` 重算（写 `exports/model-comparison/`），每个已保存标定的
中间场也可以用 `npm run recompute -- --calibration <目录>` 独立复核。

## 结论

**选定：网格插值场 grid@8px（8 像素控制格 + 双线性展开）**，已写入
`config/gain-model.selection.json` 并作为内核默认值（`gainModel: 'grid'`）。
稠密逐像素场（field）与受约束基函数（basis）保留为可切换路径：
界面“增益模型”一节、CLI `--gain-model`、标定记录 `options.gainModel`。

## 候选与场景

候选（`tools/compare-gain-models.js`）：

- `field`：稠密逐像素增益（历史基线，无压缩）；
- `grid@{8,12,16,24,32}px`：粗控制格 + 双线性插值，节点取支撑窗内可靠
  观测的**加权中位数**（对遮挡边缘稳健），无效节点按邻点跳数填充；
- `basis@{2,3,4,5}`：对数域多项式基（岭正则 λ∝阶次² + IRLS 稳健迭代），
  `exp()` 保证增益为正。

场景（同一合成真值链 `src/core/synthetic.js`，512×384、16bit）：

- **standard**：径向渐晕 0.42、尘埃圆盘、矩形遮光板、热像素、
  36×38 饱和块（约 0.7% 像素）；
- **stress**：渐晕加强到 0.55，饱和块放大到 120×110（约 6.7% 像素），
  检验稀疏无效区的退化行为。

每个候选跑 3 次取耗时中位数。估计时**最后一帧参考被留出**，不参与估计，
专门用于检验未见过图片的补偿效果。

## 验收门控与评分

门控（全部通过才允许更新选择文件）：

| 门控 | 阈值 |
| --- | --- |
| 增益精度（可信区均值相对误差） | < 5% |
| 留出帧平坦度 | cvAfter < 0.5 × cvBefore |
| 纹理保持（高通比值） | [0.8, 1.25] |
| 低亮度稳定性（真值增益≥2 区） | 平均误差 < 15% 且封顶比例 < 2% |
| 噪声放大 | 不超过所施加倍率上限 |
| 压力场景留出帧平坦度 | 同上 |
| 退化局部性 | 退化像素 < 20% 且无死节点 |

评分（越低越好，仅用于在通过门控者中排序）：增益误差 0.30、
留出帧平坦度 0.25、低亮度稳定 0.20、纹理保持 0.10、模型大小 0.15。

补充观测：

- **过拟合噪声**：6 倍噪声（2520 DN）下 grid@8 的增益误差 0.80%，
  反而优于 field 的 0.95%——中位数节点起了正则化作用；稠密场把高频
  噪声直接当作增益。
- **低亮度区**：grid@8 在真值增益≥2 区平均误差 8.3%、封顶比例 0，
  但 p99 达 45.6%（集中在遮光板/尘埃边缘的少数像素），内核校验的
  `lowLightStable`（p99<0.25）因此为 false——门控按平均误差与封顶
  比例判定通过，p99 作为已知残留风险记录在案。
- **应用成本**：应用阶段对三种模型都是同一次有界乘法（稠密场已落盘），
  3–14 ms/张（512×384，含 JIT 预热差异），与模型种类无关；模型选择
  影响的是标定耗时（grid@8 约 490 ms）与存储。

## 取舍分析

### 稀疏无效区

- **grid**：无效节点按邻点跳数填充（BFS），置信度 ×0.7^跳数，最多 8 跳；
  超出则节点判死（增益=1、置信度=0、DEAD 标志）。stress 场景的
  120×110 饱和块（6.71% 像素）产生 6.06% 退化像素、0 死节点，
  留出帧 CV 0.058、增益误差 1.07%，与 standard 几乎不变——洞的
  内部由邻域估计填补并明确标记。
- **field**：同一洞内 6.47% 像素直接判死（增益=1、不校正），无任何
  填充能力；洞外精度与 grid 相当。
- **basis**：全局曲面不受局部缺失影响，但缺失区边缘的置信度统一降为
  0.75（UNOBSERVED），没有”离空洞多远”的概念；且洞的存在会轻微
  拖动整张曲面（stress 误差 4.88% vs standard 3.03%）。

### 局部阴影（尘埃、遮光板）

- **grid**：节点取支撑窗内可靠观测的加权**中位数**，遮挡边缘两侧多数派
  决定节点值，阴影保持局部（standard 低亮度误差 8.3%）。早期版本用
  加权均值时误差 10.7%，阴影被拖向亮侧。
- **basis**：全局光滑曲面**无法表达**细小遮光——遮光板/尘埃区残差
  58–62%，直接触发低亮度门控失败。这正是基函数路径的结构性限制，
  不是参数问题（2–5 阶全部失败）。

### 基函数无法表达细小遮光时的处理政策

基函数拟合后逐像素计算对数残差，残差超过 `basisResidualSigma`（默认 4）
倍稳健标准差的可靠观测被标记 **MODEL_UNFIT（标志位 16）**：

1. 该像素置信度降为 0.25（UNFIT_CONFIDENCE）；
2. 应用阶段按置信度 taper 把校正衰减向 1——**报告遮光，而不是用一个
   表达不了它的模型强行校正**；
3. 未观测像素置信度 0.75；标定记录 `gainModel.unfitFraction`，
   超过 3% 时记录警告；界面对 MODEL_UNFIT 比例出异常条。

### 插值方案缺少邻点时的退化

1. 节点支撑窗内可靠观测不足（加权支撑 < 3）→ 节点无效；
2. 无效节点由最近有效节点按跳数填充，每跳置信度 ×0.7，像素插值后
   标 **GRID_DEGRADED（标志位 32）**；
3. 8 跳内无有效邻点 → 死节点：增益=1、置信度=0、**DEAD（标志位 128）**，
   应用阶段 taper 到原值；
4. 标定记录 `directNodes/filledNodes/deadNodes/degradedPixelFraction`，
   退化像素超 5% 或存在死节点时记录警告；界面异常条同步显示。

## 模型大小与持久化

512×384 单通道示例（演示标定实测，`npm run recompute` 可复核）：

| 模型 | 紧凑参数 | 稠密场 | 比例 |
| --- | --- | --- | --- |
| field | – | 786432 B | 100% |
| grid@8px | 12288 B（model.bin）+ 107 B（model.json） | 786432 B | 1.58% |
| basis@4 | 120 B（15 项 Float64 系数） | 786432 B | 0.015% |

标定目录始终保存稠密 `gain.bin`（应用路径不变），grid/basis 额外保存
`model.bin`（Float32 节点 / Float64 系数）与 `model.json`（几何元数据）。
`tools/recompute-metrics.js` 会把紧凑模型重新展开并与 `gain.bin` 逐像素
对比（要求最大相对偏差 < 1e-4），同时重算可信比例、标志位比例、低亮度
增益分布与应用耗时——**所有发布数值都能从保存的中间场重算**。

旧标定（schemaVersion 3，无模型文件）按 field 模型正常加载，无需迁移。

## 选择文件的安全语义

`config/gain-model.selection.json` 只在**全部验收门控通过**时由
`tools/compare-gain-models.js` 重写；任何候选失败时脚本退出码 3，
已确认的选择原样保留（`commitSelection`，有测试覆盖）。日常标定不读
此文件——它是实验决策的审计记录，默认参数以 `src/core/options.js`
的 `DEFAULTS.gainModel` 为准。
